# Automated editor and retail-game testing

## Finding the PS2 Save Keeper from a fresh lobby arrival

From the Terminal Area where a newly created or called Digimon appears, take
the bridge to the **left**. Confirm **Central Area → Go to the destination**
and wait for the area to finish loading. From the Central Area arrival point,
walk left toward the central building, then up into the recessed counter
between two green-topped terminals. The attendant there is the **Save Keeper**;
the location label at the bottom of the screen confirms the name. Approach the
attendant and press Cross to talk.

The raised circular platforms in the Terminal Area are gates/healing facilities;
the Save Keeper is across the bridge in Central Area. Private route captures
are in `../Decomp/local/ps2-box-research/`: `bridge.png` shows the destination
prompt, `central-spawn.png` the arrival point, and `central-keeper.png` the
counter with the **Save Keeper** location label.

## Desktop agent controls

Build the real Tauri app with its optional agent interface:

```sh
npm run build
cargo build --manifest-path src-tauri/Cargo.toml --features agent-control,tauri/custom-protocol
python3 tools/agent.py --session /tmp/dw4orge-agent.json start --binary src-tauri/target/debug/dw4orge
python3 tools/agent.py --session /tmp/dw4orge-agent.json snapshot
python3 tools/agent.py --session /tmp/dw4orge-agent.json click New
python3 tools/agent.py --session /tmp/dw4orge-agent.json select 'Story preset' 'After World 1'
python3 tools/agent.py --session /tmp/dw4orge-agent.json fill 'Player name' TEST
python3 tools/agent.py --session /tmp/dw4orge-agent.json click Create
python3 tools/agent.py --session /tmp/dw4orge-agent.json dialog save /tmp/test-save.ps2
python3 tools/agent.py --session /tmp/dw4orge-agent.json click Save
```

The server binds only to loopback, defaults to port 17365, and requires a random
bearer token generated by the launcher. The session file is created exclusively
with mode 0600; the launcher rejects paths inside any Git repository. The feature and `DW4_AGENT_TOKEN`
are both required to start the server. Ordinary builds expose no agent commands
or listener. A feature-enabled build without the token uses normal file dialogs.

`click`, `fill`, `select` and `check` operate on the actual rendered controls. Labels are
matched within the active dialog when one is open. `fill` waits for React to
commit the input change before blurring a numeric field. `snapshot` reads the
webview, and `eval` runs an async-capable script there. Linux `screenshot` also
needs xdotool and ImageMagick. `close` requests the native window-close event and
respects the unsaved-work guard.

`dialog open|save [path]` queues one native file-picker result; omit the path to
cancel. The next corresponding UI action consumes it. This substitutes only the
platform picker: the frontend draft, validation, Tauri commands, Rust backend and
actual file writes remain the production paths. A mismatched or missing queued
response fails explicitly.

The token grants control of the editor session, including JavaScript evaluation.
Do not share it or publish the session file. Protocol tests cover authorization,
request bounds, truncated bodies, script parsing and Unicode transmission.

## Native editor regression runner

```sh
cargo build -p dw4cli
python3 tools/e2e.py --session /tmp/dw4orge-agent.json --cli target/debug/dw4cli --output /tmp/editor-results
```

The output directory must not already exist. The runner creates and reopens raw
saves and memory cards for all six presets plus the default new game, on each
editor difficulty setting. It checks bytes through the CLI and writes a
`cases.json` manifest for game testing. Subsequent edit tests use a separate card,
preserving the generated cases.

It also exercises character values, techniques, power-ups, disk counts, normal
item selection, equipment, automatic mod-chip inventory, the last bank page,
story-preset replacement, all sixteen species, species-switch protection,
undo/redo, Ctrl+O discard protection, cancelled dialogs, error handling and the
native close guard.

## Cold-boot retail regression runner

Supply the emulator, pristine disc, an isolated profile template containing
`bios/` and `inis/PCSX2.ini`, and the private PINE client explicitly:

```sh
python3 tools/game_e2e.py \
  --emulator /path/to/pcsx2-qt \
  --iso /path/to/pristine-disc.iso \
  --profile-template /path/to/test-profile/PCSX2 \
  --pine-client /path/to/pine-client-scripts \
  --tessdata /path/to/english-tesseract-data \
  --cards /tmp/editor-results \
  --output /tmp/game-results \
  --pine-slot 28014
```

This requires the private PCSX2 agent protocol, Pillow, Tesseract with English
trained data, and Python 3.14 for zstd-compressed savestate ZIPs. Select an unused
PINE slot. The runner creates its own profile and writable card copies. It never
loads an existing savestate to install a card: each case starts from a cold boot.
The input disc's checksum is checked before and after testing.

For each card, it discovers the difficulties actually offered by the game and
cold-boots each one. It confirms the selected difficulty, all 43 restored flag
mappings and the eleven restored folders from live retail properties. After the
opening dialogue, it checks the real player controller's enabled/frozen state
and response to opposite stick inputs. Captures accompany each result. The
current-model scratch pointer is deliberately avoided because it can identify
an NPC instead of the player.

`--case filename.ps2` limits the run to a manifest case and may be repeated.
`report.json` records each built/loaded difficulty pair and its available modes.
This checks save acceptance, restoration and player control on the USA PS2
release. It does not claim complete campaign, boss, quest, other-region, or
other-platform playthroughs.

## Story reference regeneration

```sh
python3 tools/gen_story_reference.py --lua /path/to/corrected-retail-disassembly
```

The generator requires the title load and character save mappings to agree, then
extracts the debug progression checkpoints. Its output records game entry/chunk
identifiers and numeric data, without local source paths or game binaries. The
old Python fixtures remain useful for non-story format parity; story correctness
is pinned against `crates/dw4core/tests/fixtures/flags/retail.json` and retail runs.

## Verified results

The regression run covers 21 generated cards and all difficulties offered for
those cards: 26 cold boots (21 Normal, three Hard, two Very Hard). Every run
passed live difficulty, flag/folder restoration and player-control checks; the
pristine disc checksum remained unchanged.

The native editor runner passed 34 checks, including all sixteen species,
advanced values, manual flag toggles, both data-loss guards and native close
cancellation. The automated suites passed 291 Rust tests, 154 frontend tests,
and four agent-protocol tests. Formatting, type checking, linting, both shell
feature configurations and palette contrast checks also passed. Generated game
cards, BIOS copies, states, screenshots, tokens and machine-specific logs remain
outside the tracked source.


## Regional validation (0.2.0)

The existing automatic retail runner above uses USA addresses and English OCR;
its preset matrix remains a USA test, not a claim of regional campaign coverage.
European and Japanese support was checked separately with pristine regional discs
and matching European v2.00 / Japanese v1.00 BIOSes. For each region, a generated
Dorumon card loaded into gameplay, the Central Area Save Keeper successfully
saved over it, and the written character loaded into gameplay after a cold boot.
Both written files were 81,920 bytes, version 4, with identical mirrored blocks
and valid additive checksums. Local game cards and captures remain outside Git.

Automated regional regression checks cover all three card identities, regional
icon metadata and ECC, region preservation across edits and Save As, backups,
raw exports, and mixed-region selection with the other save preserved. CLI and
UI tests cover region selection. To repeat game acceptance with the integrated
writer, create a card using `dw4cli new --region europe|japan --out test.ps2`, mount
it in an isolated PCSX2 profile and follow the load/save/cold-boot sequence above.


## Xbox validation (0.4.0)

The Xbox suite adds synthetic signed four-box files and fragmented FATX images.
It checks selected-box isolation, preservation of other boxes/unknown padding,
filesystem and unrelated-file preservation, signatures, backup/Save As behavior,
image-to-file export, malformed geometry/chains/cross-links, invalid signatures,
external-write conflicts and Normal/Advanced bank packing. Frontend tests cover
box-switch discard/cancel behavior. The native Tauri app was also driven through
HDD-file and memory-unit edits, all four box choices, Save As and the discard
guard; independent HMAC checks verified its output and untouched boxes.

`cargo run -p dw4ipc --example xbox_validation -- input output [selection]`
creates a controlled field matrix through the same service used by the app.
It requires an existing retail character and writes a separate output. It does
not launch xemu or attach media. `tools/xbox_save_probe.py` provides independent
signature/field checks using a local XBE. No Xbox game/save binaries are fixtures
in the repository. See [Xbox research](xbox-save-research.md) for retail results,
private evidence locations and the memory-unit mounting format.


Final v0.4.0 checks passed 307 Rust tests (including doctests), 158 frontend
tests, four Tauri agent tests and three independent Python probe tests, plus
Rust formatting/Clippy, TypeScript, ESLint, production frontend build and palette
contrast checks. Retail USA loaded an app-written slot-A image and re-saved to
HDD; retail Japan loaded the final slot-B image and re-saved to HDD. The final
Japanese round-trip retained every tested editable field group, including both
packed bank items and persistent story milestone 20. Only menu/runtime story
flags 908/912 changed. Native screenshots checked the content-sized box selector
and summary spacing.

## PS2 character boxes (0.5.0 / schema 6)

The retail USA game saved a second character into box 2 of the same
`BASLUS-20836savedata` file. An independent FAT walk/extraction found the second
character at `+0x2008` in each `0xA000` mirror, establishing the `0x2000` box
stride. These bytes were previously misidentified as padding in one-box saves.

`cargo run -p dw4ipc --example ps2_box_validation -- input.ps2 output.ps2 'ps2#2'`
creates the controlled field matrix through the same service used by the app.
It edits an existing occupied box and never initializes an empty one.
The retail game cold-booted the output and displayed `PS2BOX2`, level 17 in
box 2 alongside the untouched `TST` in box 1. It loaded that character into the
lobby, then saved it again through the Save Keeper. The resulting save matched
name, species, level/EXP, BIT, X-Data, junk counter, all techniques/power-ups,
inventory, equipment/mod sockets, disks, bank balance/items, difficulty and
story folders. Persistent milestone 20 survived; only runtime/menu flags 908
and 912 differed. Both checksums verified. Independent byte comparisons
confirmed box 1 was unchanged by both the editor write and the retail resave.

The native desktop app verified both occupied choices, Cancel retaining an
unsaved draft, Discard switching characters, selected-box retention through
Save/Save As, and switching back to the unchanged first character. Its captured
summary shows box 2 and the saved values without clipping. Private cards,
captures and JSON reports are under `../Decomp/local/ps2-box-research/`.
The source card and pristine disc were not edited; only isolated copies were
attached to the test emulator.

Automated coverage includes all four boxes, holes/default selection, empty and
invalid choices, all three regional card identities, raw/card export, repeated
saves, donor-card preservation, external-save conflicts, IPC selection failure
retaining the session, CLI selection and the desktop discard guard. Final checks
passed 314 Rust tests (including doctests), 159 frontend tests and four Tauri
agent tests, plus formatting, Clippy, TypeScript, ESLint, production build and
palette contrast. Live game coverage is USA box 2; other box/region combinations
have automated format coverage, not a claimed full retail campaign test.
